# Wingman · 设计取舍

## 0. 挂载点的一条实测经验（v0.5.2）

`shell.overlay` 在部分宿主版本里会接收条目、也会调用组件函数，但带 hooks 的组件渲染两次后不 commit（没有 DOM、没有报错、条目仍是「已注册」）。同一条 slot 里，无 hooks 的纯函数组件却能正常显示。

因此 v0.5.2 起，工具条挂在 `conversation.input.dock`（已验证可渲染），并在 `conversation.header.leading` 备一个挂载点，用「先成功挂载者负责渲染」的模块级抢锁避免重复。视觉上仍靠 `position: fixed` 贴在正文左缘，与挂载点无关。

教训：**别把「注册成功」当成「能渲染」**。以后接新 slot，先用一个无 hooks 的探针组件确认它能 commit，再搬真组件。

## 1. 为什么是浮层，不是「占一列」

DSH 的 slot 树里没有「在正文左边再挤一列」的 additive 口子：

- `sidebar` / `main.conversation` 是 `shadows-shipped-ui`——接管它们等于重写会话外壳，升级易碎
- `rightbar` 是官方侧栏，但右栏已被 better-sidebar 的文件/git 占着
- `shell.overlay` 是全帧浮层：**不参与布局、在滚动容器之外、默认点击穿透**，条目自己开 `pointer-events`

所以选 `shell.overlay`：视觉上贴左缘，物理上不改布局。代价是面板会盖住正文左侧——在 1600px 窗口下，正文居中的留白刚好接住这 308px；窄窗则退成抽屉。

## 2. 为什么是一个包

外壳（定位、拖拽、钉住、快捷键、持久化、刀谱）是最脆的部分。拆成多个包就要先做一个宿主包、再定义服务契约、再处理加载顺序——在你只有一台机器、一个用户的前提下，这些收益为零。

「让别人挂刀」不需要拆包：一个包也能暴露 `ctx.edgeDock.register()`，和 better-sidebar 的 `ctx.betterSidebar` 同一个模式。等刀稳定两周再开放。

## 3. 为什么需要一个 `input.dock` 的桥

`shell.overlay` 的 standardProps 里有 `useSessions`、`usePanelInfo` 等，**没有 `inputActions`**；而 `conversation.input.dock` 有 `inputActions`（prompt-hints 就是这么填草稿的）。

于是：本包在 `input.dock` 注册一个渲染 `null` 的组件，把 `inputActions` 交给模块内共享变量，浮层里的面板通过它插入文本。这样既拿到写入能力，又不碰宿主的输入组件、不读别人的 DOM。

## 4. 数据

`$DSH_HOME/wingman/snippets.json`，和便签墙（`$DSH_HOME/notes/notes.json`）同一套约定：

- 读一次、写整份、临时文件 + rename 原子替换
- 坏 JSON 直接报错，不静默覆盖
- 串行写（promise 队列），避免并发保存互相踩
- 首次启动写三条示例，删掉即清空

## 5. 风险与对策

| 风险 | 现状 | 对策 |
|---|---|---|
| 左栏收起后工具条偏移 | 默认 `left: 344px` | 拖拽是保底；后续试读布局变量做自适应 |
| ⌘1 与浏览器标签页切换冲突 | 已加 `preventDefault`，输入框里不触发 | 若仍打架，改成 ⌘J |
| DSH 升级后 slot 变化 | 只用 `shell.overlay` + `conversation.input.dock` 两个稳定口子 | 注册失败只 warn、不抛错，整机不受影响 |
| 面板盖住正文 | 308px 落在居中留白里 | 点外面/Esc 即收；钉住是显式选择 |
| 片段变成第二个便签墙 | v0.1 只有片段，不含便签 | 「记」刀走共享数据，不新建存储 |

## 6. v0.2 看刀的数据来源（备忘）

- 上下文占用：Host `tokenMeter.measure(session)`，经本包路由暴露成只读 JSON
- 运行中任务：`subagents.listChildren()` / 任务列表服务
- 定时：schedule 服务（具体接口在动手前查 `cordis_inspect_query`）
- 原则：只读、不轮询，打开面板才取一次

## 6.3 「转」为什么先做非 AI 部分

选中文字 → 存成便签 / 片段 / 引用 / 复制，这四件事不需要模型，却占了「转」日常使用的八成：读到一段有用的话，最常做的是留下来或引回去，而不是让它重新写一遍。

选区来源只读 `window.getSelection()`，并且排掉三类：落在 `input`/`textarea`/`contenteditable` 里的（那是输入框自己的选区）、落在本插件自己的面板里的（避免自我引用）、短于 3 字的（误触）。

紫色便签只在有选区时出现——它不是常驻入口，而是「手上有东西时才出现的一把刀」。点它时在 `pointerdown` 里 `preventDefault`，否则浏览器会先清掉选区，click 时已经拿不到文字了。

AI 改写（v0.4.1）需要先解决「用哪个模型、走哪条服务、要不要计费提示」，所以这一版先不动。

## 6.4 「记」为什么不新建存储

便签墙和跟进各自已经有本机 JSON + 内存态 + 写入队列。本插件如果自己再存一份，就会出现两个真相，迟早对不上；如果直接写他们的文件，又会被它们的内存态覆盖。

所以「记」走它们**已有的 HTTP 接口**（`/dsh-sticky-wall/api/notes`、`/followup/add`）：请求进它们的进程，由它们自己校验、排队、落盘，本插件只负责「写一句、发出去、收回面板」。代价是依赖这两个接口的形状——但那是它们对外暴露的稳定面，比自己读文件安全得多。

同一原则也会用在 v0.4「转」上：它能调到的就调，不复制状态。

## 6.5 颜色不是装饰，是入口

工具条上的颜色数 = **已经能点的入口数**，不是设计稿上的配色。

- 每把刀在 `BLADES` 里带 `tone`（rose / sky / mint / violet…），`state: 'live'` 才渲染
- 规划中的刀只在刀谱里出现，不占工具条、不占颜色
- 目录按钮（＋ 刀谱）是中性灰：它是「看全部」的入口，不是一把刀
- 好处：加刀就自然多一颗色，撤刀就少一颗；不用再维护一套和功能脱节的配色

## 6.55 「更多」是菜单，不是路线图

第一版把「更多」做成了带版本号和「规划中」的路线图——那是给开发者看的，放在产品里只会让人以为有四个功能在排队。现在它只回答两个问题：**现在能用什么**（四行入口，点一下即开）、**怎么调**（吸附开关、位置复位）。路线图留在 ROADMAP.md 里。

## 6.6 AI 改写为什么能直接复用会话模型

宿主有 `llm.stream(GenerateOptions)`，路由从 `session.requestHeader().config` 取，取不到退到 `agentDefaultModel.currentSelection()`——这正是 `dsh-prompt-hints` 走过的路。所以不需要让用户再配一次 key，也不会另开一条计费通道：用的就是当前会话那个模型。

限制：每次点击 = 一次模型调用（有成本），25 秒超时；错误（无路由、额度、空回复）都转成一句人话提示，不抛给页面。

## 7. 吸附：怎么在不读别人 DOM 的前提下找到侧栏右缘

需求是「既能自由拖，也能贴住左侧栏」。真正的依赖只有一条：**正文列的左边界 = 侧栏右缘**。

测量顺序（都失败就保持原位，绝不让工具条飞出屏幕）：

1. **找左栏本体**：从左边缘 2/8/16px 处 `elementFromPoint`，沿祖先链找「left≈0、宽度 ≤45%、高度 ≥50%」里最宽的那个节点——那就是贴着窗口左缘的那一列，取它的 `right`。比「两点求共同祖先」稳：后一种在左栏折叠后会掉进正文里居中的内层容器，看起来像「飘到中间」
2. **共同祖先兜底**：取「正文中心」与「最左侧」的最近共同祖先，取正文一侧子节点的 `left`，并收紧到窗口宽度 35% 以内
3. **布局变量**：试 `--dsh-sidebar-width`、`--dsw-sidebar-width`、`--dsh-layout-sidebar-width`、`--dsw-layout-sidebar-width`；量到 40px～窗口 45% 之间才认
4. 都没有 → 返回 `null`，工具条停在原位（不猜、不乱跳）

跟随策略：吸附态下每 0.6s 重测一次 + `resize` 时重测，覆盖侧栏折叠/展开与窗口缩放。之所以用轮询而不是 `ResizeObserver`，是因为折叠可能只改内联宽度、不触发元素本身尺寸事件；0.6s 对几次 `elementFromPoint` 来说可以忽略。若哪天宿主给出侧栏尺寸事件，换成订阅。

交互：拖动时离边缘 ≤ 56px 显示参考线；松手在阈值内即吸附，并把横向偏差记成偏移量（±140px），以后按 `边缘 + 偏移` 定位——量得不准也能自己拉回来。磁铁 tooltip 会显示当前量到的像素，便于没有浏览器控制时排查。
