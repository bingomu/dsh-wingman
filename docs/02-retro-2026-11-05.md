## 二、事故与根因

### 事故 A：细条一直不显示（仍未 100% 定论）

- 现象：项注册成功；组件被渲染 **2 次**；`挂载✗`、`DOM 无`；无报错；同 slot 内无 hooks 的极简组件正常显示
- 已排除：注册失败、位置飞出屏幕、被遮挡、CSS 未加载
- 处置：0.5.2 起细条挂到 `conversation.input.dock`（已验证能渲染），并在 `conversation.header.leading` 备一个挂载点，用「先挂上者负责渲染」的抢锁避免重复
- 结论：**注册成功 ≠ 能渲染，能渲染 ≠ 可见**。overlay 对带 hooks 组件的处理在 rc.5 上有问题，绕开比硬碰划算

### 事故 B：客户端整个打不开（最严重）

- 现象：启动弹「应用无法启动或已意外停止」；日志 `web boot: 1 entry did not activate / dsh-wingman: import failed`
- 直接原因：0.5.2 用「按位置切片」两次删代码，都切过头
  1. 删「选区/测量」段时连带删掉 `currentSelection`、`measureEdge` 等 → 细条一渲染就 `measureEdge is not defined`
  2. 删「诊断」段时连带删掉 `API`、五个存储键、`SNAP_PX`、**zh / en 两本字典** → `apply()` 抛 `ReferenceError: zh is not defined`
- 链条：**apply 抛错 → 插件入口 inactive → web boot 失败 → 整个桌面端起不来**（不是「少一个页签」）
- 次生：编辑器写到一半（`try {` 缺 `catch`）被 HMR 读到，产生一次 `import failed`

### 事故 C：重启脚本卡住

- `osascript quit` 后应用不退，SIGTERM 也没杀掉，脚本 10 秒后报「未能退出」，后面的清 cookie、重开都没执行

### 事故 D：工作区切换导致写入被拒

- 会话工作区从 `deepseek-harness/default-workspace` 切到 `DSH Plugin`，插件源码仍在旧目录，之后每次改文件都要申请跨目录权限

### 事故 E：设置每次重启就丢

- 位置/吸附/钉住/当前入口存在 `localStorage`，而桌面端每次重启换端口 → 同源策略下 localStorage 是新的 → 设置全丢

### 事故 F：探针占了产品界面

- 为了定位，黄条/绿条/蓝条直接进了界面，用户看到的是调试信息而不是产品

## 三、做对了什么

- 全部通过 slot 扩展，没有替换宿主 UI，也没有读别人的 DOM/样式
- 「记」复用便签墙与跟进的 HTTP 接口，不复制存储
- 数据全在本机，无网络请求
- 15 个测试覆盖存储、状态采集、模型代理
- 版本号、CHANGELOG、ROADMAP、设计文档同步
- 探针思路本身有效：用无 hooks 对照组把问题切成两半

## 四、做错了什么（流程缺口）

1. **用切片批量删代码**——这是这次事故的直接原因，也是最危险的编辑方式
2. 删完没有立刻跑语法/引用检查就继续改
3. 没有「上一版可用代码」的即时备份与一键回滚
4. 没有「装之前先在桩里跑一遍 factory + apply」的门槛（现已补）
5. 诊断功能没有开关，直接进了生产界面
6. 持久化选错层（localStorage 对桌面端是易失的）
7. 重启依赖一个会超时的脚本，没有强杀兜底

## 五、已落地的护栏

- `npm run check` 现在包含 `scripts/check-client.mjs` 四道关：
  1. 能解析  2. 常量声明齐全  3. zh/en 字典键对齐  4. 用桩跑 `factory` + `apply`，断言注册了哪些 slot、是否注册字典
- 顶层的 `zh`/`en`、`API` 等常量必须在 `apply` 之前声明（否则入口激活失败）
- 改动后先 `npm run check`，再刷新页面；改 host 才重启

## 六、待做（按优先级）

### P0 稳定（先做，不碰功能）

1. **last-known-good 备份 + 一键回滚**：每版复制 `client.js` 到 `backup/`，回滚 = 覆盖 + 刷新（30 秒内）
2. **apply 兜底**：整个 `apply()` 包 try/catch，失败只禁用本插件，绝不让入口 inactive
3. **诊断开关**：探针只在 `?dshSwiss=debug` 或 localStorage 标记下渲染，默认关
4. **状态上移**：位置/吸附/钉住/当前入口改存 `~/.dsh/wingman/state.json`（host 侧），重启不丢
5. **重启脚本强杀**：osascript 失败后 `pkill`，再 `open`
6. **项目收敛**：把项目放回当前工作区，消除跨目录审批

## 七、红线（写进每次改动前的检查）

- 绝不按行号/索引批量删代码；只做小步 `edit`，每步 `node --check`
- 任何 `apply()` 顶层代码都必须能容忍缺服务/缺文件
- 改动后顺序：`npm run check` → 刷新 → 看 console 有没有 `[dsh-wingman]`
- 保留上一版可用的 `client.js`，出问题先回滚再排查
- 诊断代码不进生产 UI，必须走开关
